# ENTEGO BUSINESS FOUNDATION v2.0 — EVENT ECOSYSTEM

Owner / Final Authority: Arda
Status: OFFICIAL FOUNDATION / LOCKED
Startup command: `KAI ENTEGO START`

## Core Vision
ENTEGO is not limited to a DJ-booking app. ENTEGO is an **Event Ecosystem Platform** for Indonesia: a commerce and operating layer connecting customers, talent, vendors, organizers, venues, booking, payments, packages, and eventually managed events.

Long-term investor narrative:
> ENTEGO is building the commerce and operating platform for Indonesia's event economy.

## Ecosystem Participants
ENTEGO must be designed to support the following participant groups from the foundation stage:

### Customer
Can search, compare, book, and pay for one service or an event package.

### ENTEGO Professional Partner
Professional partners are grouped by business function, not treated as one generic vendor type.

1. **Talent**
   - DJ
   - MC
   - Band
   - Dancer
   - Live Performer
   - Other event talent

2. **Production**
   - Sound
   - Lighting
   - Stage
   - LED / visual production
   - Decoration / production support

3. **Services**
   - Photography
   - Videography
   - Makeup
   - Catering
   - Transport
   - Other supporting event services

4. **Organizer**
   - Event Organizer (EO)
   - Wedding Organizer (WO)
   - Party Planner
   - Corporate Event Planner

5. **Venue**
   - Club
   - Villa
   - Hotel
   - Ballroom
   - Beach Venue
   - Other event venues

EO and WO are official ENTEGO partner categories from Phase 1. They are strategic partners, not default competitors.

## Phase Model

### PHASE 1 — Marketplace / Enabler
ENTEGO operates as a marketplace and transaction enabler.

Customer can book individually:
- DJ / MC / live performer
- sound / lighting / stage
- transport
- photographer / videographer
- venue
- EO
- WO
- supporting vendors

Commercial flow:
`Customer → ENTEGO → Professional Partner`

Primary ENTEGO monetization:
- commission
- platform / transaction fee where appropriate

Hard rule: ENTEGO does **not** position itself as an organizer competing against its EO/WO partner base in Phase 1.

### PHASE 2 — Booking + Package Builder
Add multi-vendor package commerce while keeping EO/WO capable of acting as the lead organizer.

Core capability: **Build Event Package**.

Example package structure:
- Package: Bali Wedding Package
- Lead organizer: WO / EO
- Venue
- DJ / entertainment
- Photography / video
- Decoration
- Other services
- One combined customer price

The package system should allow partners to bundle ecosystem supply instead of forcing customers to book every vendor individually.

Potential future product objects:
- package owner / lead organizer
- package components
- included vendor/service references
- customer-facing package price
- package availability
- package booking lifecycle
- package revenue allocation

### PHASE 3 — ENTEGO Managed Events
Managed Events becomes a separate service layer after marketplace supply, trust, and operating processes are mature.

Customer can provide a high-level brief instead of selecting vendors individually, for example:
- wedding for a target guest count and budget
- corporate party for a target audience size
- full event execution request

Commercial flow:
`Customer → ENTEGO as Project Lead → ENTEGO Ecosystem Partners`

Possible ENTEGO revenue components:
- management fee
- vendor margin
- applicable platform fee

Managed Events is allowed only when:
1. the customer explicitly asks ENTEGO to manage the overall event; or
2. the event is created/owned by ENTEGO itself.

It must not be used as a mechanism to systematically disintermediate or poach customers from EO/WO partners.

## Partner Ecosystem Protection Rule
ENTEGO must grow supply-side trust before becoming a direct project lead at scale.

Hard principles:
- EO/WO are partners first.
- Do not design Phase 1 messaging that implies ENTEGO will replace organizers.
- Do not use partner/customer data to unfairly bypass the partner relationship.
- Keep organizer attribution and package ownership visible where applicable.
- Managed Events must have a clearly separate operating model from ordinary marketplace bookings.

## Demand Creation Layer — Future
After the marketplace is healthy, ENTEGO may create its own demand through owned event brands or programs, such as:
- ENTEGO Sessions
- ENTEGO Festival
- ENTEGO Wedding Showcase
- ENTEGO Creator Events

This is a later expansion layer, not a Phase 1 dependency.

## Strategic Network Effect
The intended network is:

`Customer ↔ Talent ↔ Vendor ↔ EO/WO ↔ Venue ↔ Packages ↔ Booking/Payment ↔ ENTEGO`

Future managed-event demand can then be fulfilled using the same verified ecosystem.

The strategic objective is to increase both:
- transaction frequency through single-service marketplace bookings; and
- average transaction value through packages and managed events.

## Legal / KBLI Governance
Legal classification is activity-based and must be verified against the final ENTEGO operating model when the legal entity/NIB is prepared.

Verified foundation:
- KBLI 2025 is the current official BPS classification framework replacing KBLI 2020.
- Older `82302 Jasa Penyelenggara Event Khusus (Special Event)` is a KBLI 2020 classification and must not be blindly copied into a future ENTEGO legal setup.

Hard rule:
- Do **not** permanently lock a specific KBLI code for ENTEGO yet.
- Before incorporation/licensing, map the actual final activities (marketplace/platform, organizer activity, event production, venue-related activities, digital platform operations, etc.) against the then-current BPS/OSS classification and licensing requirements.
- Codes mentioned in informal discussion such as `90391` or `9690` are **UNVERIFIED FOR ENTEGO** until confirmed directly against official BPS/OSS definitions for the precise activity.
